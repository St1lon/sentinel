# Отчёт по ДЗ 4: метрики приложения и Victoria Metrics

Приложение — Sentinel, сервис мониторинга доступности сайтов. Развёрнут
в minikube в namespace `sentinel`.

Манифесты — `k8s/`, values чарта — `k8s/monitoring/vm-single-values.yaml`,
код метрик — `internal/infra/metrics/`.

---

## Стек

- Go 1.24, chi, pgx, PostgreSQL 17;
- три процесса: `api` (2 реплики), `worker`, `cleanup` (CronJob), плюс nginx
  со статикой;
- клиентская библиотека метрик — `github.com/prometheus/client_golang`;
- хранилище метрик — Victoria Metrics v1.154.0, чарт
  `vm/victoria-metrics-single` 0.49.0, namespace `monitoring`.

Метрики отдаются в формате OpenMetrics на выделенном порту `9090`, путь
`/metrics`. Порт не входит в Service приложения.

---

## Экспортеры

| Что экспортируется | Чем | Модель |
|---|---|---|
| рантайм Go и процесс (`go_*`, `process_*`) | коллекторы `collectors.NewGoCollector()` и `NewProcessCollector()` из `client_golang` | pull |
| HTTP-слой API (`sentinel_http_*`) | middleware `internal/transport/http/middleware/metrics.go` | pull |
| бизнес-метрики (`sentinel_*`) | `client_golang`, адаптеры в `internal/infra/metrics/` | pull |
| PostgreSQL (`pg_*`) | `quay.io/prometheuscommunity/postgres-exporter:v0.20.1`, сайдкар в поде базы, порт 9187 | pull |
| разовая задача очистки (`sentinel_cleanup_*`) | `client_golang` + POST в `/api/v1/import/prometheus` | push |

Метка `route` в метриках HTTP-слоя — шаблон маршрута chi
(`/api/v1/monitors/{monitorID}`), а не путь запроса.

## Развёртывание Victoria Metrics

```bash
helm repo add vm https://victoriametrics.github.io/helm-charts/
helm upgrade --install vm-single vm/victoria-metrics-single \
  --namespace monitoring --create-namespace \
  -f k8s/monitoring/vm-single-values.yaml
```

То же одной целью: `make monitoring-up`. В values переопределено
`server.scrape.enabled: true`, размер PVC и лимиты.

Доступ:
`kubectl port-forward svc/vm-single-victoria-metrics-single-server -n monitoring 8428:8428`,
дальше `/vmui` и `/targets`.

## Сбор метрик

Поды `api`, `worker` и `postgres` помечены аннотациями:

```yaml
annotations:
  prometheus.io/scrape: "true"
  prometheus.io/port: "9090"     # у postgres — 9187
  prometheus.io/path: "/metrics"
```

Порт из аннотации объявлен в `containerPort` — без этого job
`kubernetes-pods` отбрасывает таргет правилом `keep_if_equal`.

| Под | Порт | Что отдаёт |
|---|---|---|
| `api` (2 реплики) | 9090 | рантайм, HTTP-слой, бизнес-метрики API |
| `worker` | 9090 | рантайм, проверки, инциденты, срез состояния |
| `postgres-0` | 9187 | `pg_*` от экспортера |
| `cleanup` (CronJob) | — | отдаёт сам, push-моделью |

## Бизнес-метрики

| Метрика | Тип | Метки | Что означает |
|---|---|---|---|
| `sentinel_probes_total` | counter | `kind`, `result` | выполненные проверки мониторов по виду и результату (`up` / `down`) |
| `sentinel_probe_latency_seconds` | histogram | `kind` | время ответа проверяемой цели |
| `sentinel_incidents_opened_total` | counter | `kind` | открытые инциденты: цель упала и порог подряд неудач пройден |
| `sentinel_incidents_resolved_total` | counter | `kind` | закрытые инциденты: цель снова отвечает |
| `sentinel_auth_attempts_total` | counter | `operation`, `result` | попытки регистрации и входа по результату (`success` / `failure`) |
| `sentinel_monitors_created_total` | counter | `kind` | созданные мониторы |
| `sentinel_monitors_deleted_total` | counter | — | удалённые мониторы |
| `sentinel_monitors` | gauge | `status` | сколько мониторов сейчас в каждом статусе (`up`, `down`, `pending`, `paused`) |
| `sentinel_incidents_open` | gauge | — | сколько инцидентов открыто прямо сейчас |

Метрики разовой задачи очистки, отдаются push-моделью:

| Метрика | Тип | Что означает |
|---|---|---|
| `sentinel_cleanup_checks_deleted` | gauge | сколько записей проверок удалил последний запуск |
| `sentinel_cleanup_duration_seconds` | gauge | сколько работал последний запуск |
| `sentinel_cleanup_last_success_timestamp_seconds` | gauge | время последнего успешного завершения |

Счётчики и гистограммы пишутся в HTTP-хендлерах и в воркере, gauge состояния
снимает воркер раз в `WORKER_STATS_INTERVAL` (15 с) запросом в базу.
