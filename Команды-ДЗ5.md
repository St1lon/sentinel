## 1. Кластер и образы

```bash
minikube start
```

Первый запуск, если кластера ещё не было:
`minikube start --driver=docker --container-runtime=containerd`

Образы собираются хостовым Docker и загружаются в кластер. `minikube image
build` здесь не подходит: его `--build-opt` не принимает `build-arg`, а без
`SERVICE` соберётся api под чужим именем.

Образ `api` обязательно пересобрать, даже если он уже в кластере: в нём новая
шкала бакетов гистограммы (край `0.3`, без него SLI скорости будет пустым)
и chaos-middleware, без которого не сработает демонстрация.

Если остальные образы уже в кластере, нужны `prober` и `api`:

```bash
docker build -t sentinel/prober:dev --build-arg SERVICE=prober --build-arg VERSION=k8s -f deployments/Dockerfile .
docker build -t sentinel/api:dev --build-arg SERVICE=api --build-arg VERSION=k8s -f deployments/Dockerfile .
minikube image load sentinel/prober:dev sentinel/api:dev
kubectl rollout restart deploy/api -n sentinel
```

Все с нуля:

```bash
docker build -t sentinel/api:dev     --build-arg SERVICE=api     --build-arg VERSION=k8s -f deployments/Dockerfile .
docker build -t sentinel/worker:dev  --build-arg SERVICE=worker  --build-arg VERSION=k8s -f deployments/Dockerfile .
docker build -t sentinel/cleanup:dev --build-arg SERVICE=cleanup --build-arg VERSION=k8s -f deployments/Dockerfile .
docker build -t sentinel/prober:dev  --build-arg SERVICE=prober  --build-arg VERSION=k8s -f deployments/Dockerfile .
docker build -t sentinel/web:dev -f deployments/Dockerfile.web .
minikube image load sentinel/api:dev sentinel/worker:dev sentinel/cleanup:dev sentinel/prober:dev sentinel/web:dev
```

Проверить, что образы в кластере: `minikube image ls | grep sentinel`

## 3. Мониторинг

```bash

helm repo update vm

```

Рестарт Grafana нужен, чтобы она прочитала новый датасорс.

## 4. Демо-данные и доступ

Проброс порта к API — **отдельное окно, не закрывать**:

```bash
kubectl port-forward svc/api -n sentinel 8081:8080
```

В новом окне:

```bash
bash scripts/demo.sh http://localhost:8081
```

Скрипт напечатает slug статус-страницы. Чтобы пробер проверял и её:

```bash
kubectl set env deploy/prober -n sentinel PROBER_STATUS_SLUG=ВСТАВИТЬ_SLUG
```

Проброс порта к Victoria Metrics — **отдельное окно**:

```bash
kubectl port-forward svc/vm-single-victoria-metrics-single-server -n monitoring 8428:8428
```

Проброс порта к Grafana — **отдельное окно**:

```bash
kubectl port-forward svc/grafana -n logging 3000:3000
```

Дальше `http://localhost:3000`, логин `admin`, пароль `grafana-local-password`,
дашборд — папка `Sentinel`, `Sentinel SLO`.

NodePort по адресу `minikube ip` на Windows не работает: драйвер docker,
и адрес `192.168.49.2` живёт внутри сети Docker, с хоста он недоступен
(`ERR_CONNECTION_TIMED_OUT`). Поэтому все три интерфейса — Grafana, vmui
и vmalert — открываются только пробросом порта.

## 5. Проверка перед записью

```bash
curl -s 'http://localhost:8428/api/v1/query' --data-urlencode 'query=up{app="prober"}'
curl -s 'http://localhost:8428/api/v1/query' --data-urlencode 'query=sentinel_sli_journey_success'
curl -s 'http://localhost:8428/api/v1/query' --data-urlencode 'query=sentinel:sli:ratio5m'
```

Первый должен вернуть `1`, второй — `1`, третий — четыре серии с меткой `slo`.
Записанные ряды появляются через 1–2 минуты после старта vmalert; бюджет
ошибок и сводный SLA считаются по уже записанным рядам, им нужен ещё один
цикл — около двух минут.

Статус правил, если нужно: `kubectl port-forward svc/vmalert -n monitoring 8880:8880`

## 6. Нагрузка

Нагрузка нужна, чтобы индикаторы считались по заметному числу запросов.
Надёжнее брать её изнутри кластера: `scripts/chaos.sh` перекатывает поды api,
и проброс порта на хосте после этого отваливается вместе со скриптом нагрузки.

**Из кластера — участить пробер** (таймаут обязан быть меньше интервала):

```bash
kubectl set env deploy/prober -n sentinel PROBER_INTERVAL=2s PROBER_TIMEOUT=1s
```

Вернуть как было после записи:

```bash
kubectl set env deploy/prober -n sentinel PROBER_INTERVAL=10s PROBER_TIMEOUT=3s
```

**С хоста — скрипт** (отдельное окно, перезапускать после каждого `chaos.sh`):

```bash
bash scripts/slo-load.sh http://localhost:8081
```

## 8. Запись

В Grafana поставить диапазон `Last 15 minutes` и автообновление `10s`.
Между фазами ждать около 90 секунд: индикаторы считаются на пятиминутном окне.

```bash
# фаза 1 — база: ничего не делать, показать дашборд и назвать SLI, SLO, SLA

# фаза 2 — отказы: падает SLI доступности, растёт burn rate
scripts/chaos.sh errors 0.5

# фаза 3 — встал воркер: падает только SLI конвейера
scripts/chaos.sh off
kubectl scale deploy/worker -n sentinel --replicas=0

# фаза 4 — откат: графики возвращаются к норме
kubectl scale deploy/worker -n sentinel --replicas=1
```

Необязательные добавки, по одной за раз:

```bash
scripts/chaos.sh latency 800ms 1                          # падает SLI скорости
kubectl scale deploy/api -n sentinel --replicas=0         # все шаги пробера красные
kubectl scale deploy/api -n sentinel --replicas=2         # вернуть
```

## Если что-то не так

| Симптом | Что делать |
|---|---|
| поды `ImagePullBackOff` | образа нет в кластере, kubelet пытается тянуть его с Docker Hub — вернуться к шагу 1 и сделать `minikube image load` |
| `up{app="prober"}` пусто | проверить аннотации и `containerPort` в `k8s/70-prober.yaml`, затем `kubectl logs deploy/prober -n sentinel` |
| `sentinel:sli:ratio5m` пусто | vmalert не стартовал или не видит правила: `kubectl logs deploy/vmalert -n monitoring` |
| есть ряды `availability`, `pipeline`, `journey`, но нет `latency` | в кластере старый образ api без края бакета `0.3`: пересобрать и `kubectl rollout restart deploy/api -n sentinel` |
| пробер пишет ошибку входа | не выполнен `scripts/demo.sh` |
| в Grafana нет датасорса или дашборда | не применён `kubectl apply -f k8s/logging/` или не сделан `kubectl rollout restart deploy/grafana -n logging` |
| `ERR_CONNECTION_TIMED_OUT` на `minikube ip` | NodePort с хоста Windows недоступен, нужен `kubectl port-forward` |
| панели пустые, а запросы в vmui работают | в панели выбран датасорс VictoriaLogs вместо VictoriaMetrics |
| после `chaos.sh` графики замерли | `kubectl set env` перекатывает поды api, проброс порта и `slo-load.sh` на хосте умирают — перезапустить оба или брать нагрузку из кластера (шаг 6) |
| `chaos.sh errors` не двигает SLI доступности | в кластере образ api без правки, помечающей прерванный запрос реальным маршрутом: пересобрать api |
| бюджет ошибок в минусе, гейдж SLA красный с самого начала | 30-дневное окно помнит прошлые прогоны сбоев и смену шкалы бакетов; короткие окна при этом верны. Либо проговорить это в записи, либо стереть ряды: `curl -X POST 'http://localhost:8428/api/v1/admin/tsdb/delete_series?match[]={__name__=~"sentinel.*"}'` |
| гейдж сводного SLA и бюджет ошибок пустые | производные правила читают записанный ряд `ratio30d`: при интервале группы 5m он устаревал на окно беспамятства Victoria Metrics — интервал снижен до 1m, применить правила и перезапустить vmalert |
| SLI конвейера показывает разрыв, а не ноль | в кластере правила без `or vector(0)`: `kubectl apply -f k8s/monitoring/sli-rules.yaml` и рестарт vmalert |
